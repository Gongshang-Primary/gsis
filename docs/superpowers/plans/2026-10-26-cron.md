# GSiS v0.9.6 cron implementation plan

> **For agentic workers:** Use Superpowers test-driven development and verification-before-completion. Independent file ownership permits parallel tasks; the root integrates and reviews the result.

**Goal:** Make empty cron work cheap while retaining due operational work.

**Architecture:** Each existing service checks a small primary D1 result before broad reads. D1 and private R2 retain storage authority. Existing mutation and claim paths still decide correctness.

**Tech Stack:** JavaScript Workers, D1 SQLite, R2, Node test fixtures and Python release tooling.

**Spec:** ../specs/2026-10-26-cron-design.md

## Global constraints

Preserve manual decisions, timings, configurable flags, durable retries and sole-writer authority. No live deployment. No assertion that local timing proves the 10 ms Cloudflare CPU limit.

## Review focus

1. A report arriving during a tick must be visible to later consumers.
2. Clock-driven work must run even when source revisions did not change.
3. Expired leases must retry; future leases and retry times must not cause bulk work.
4. A newer enqueue or audit edit must survive an older job's completion.
5. Missing schema, paused authority and stale references must not be silently reported as success.
