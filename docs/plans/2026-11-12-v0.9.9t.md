## Artifacts and operational notes

Follow `docs/coordination/HANDOVER_REVIEWER.md`, Release procedure. The bundle includes numbered Roster/Deploy backend/frontend and notification/operations Worker artifacts, the unchanged emergency tool, per-file SHA-256s and `DEPLOY_STEPS.md`. Venues backend is included only if it differs from p; source comparison finds no Venues backend changes since p. Contacts backend/frontend, Calendar backend/frontend/job Worker and LORD frontend have no product changes since p and are delivered as label-only frontends where applicable; backends byte-identical to p are omitted. Where the handover's historical `optional-label-only/` layout is used, filenames beginning `REQUIRED_` are mandatory product updates, not optional label refreshes. Other frontends there are label-only updates.

The release's purpose is the first owner deployment containing #108 and #121 on top of s: the edge command queue (Deploy saves/publish through the shared queue, default direct) and the LSE notice (the duty SMC gets the dedicated LSE notice, and no "Emergency absence" message is sent for an LSE). After owner deployment, check: the stuck 11 Nov save's retry in its original browser; a new report with instructions landing at once with the note visible in My Relief Duties; the period down arrow in a Stapler draft; and a fresh LSE report — the duty SMC receives the dedicated LSE notice naming the absent teacher and date, and no "Emergency absence" message is sent for it. At deploy time the owner merges ONLY the `lse_notice` entry from `notification-worker/templates.activation.json` into the deployed `WHATSAPP_TEMPLATES_JSON` (notification/operations Workers + Roster Pages); Google stays frozen. Those live checks are owner verification, not local claims.

Full backups are **not fixed**: the missing R2 timetable part and 15-minute assembly lease failures remain separate work. A verified daily Excel/log row does not verify a full backup or restore.

Roster/Deploy require private GSIS_SECRET alignment on each active Worker/backend pair (carried by #107). Keep CALENDAR_SESSION_SECRET unchanged and independent. Retain legacy configuration names until matching new code is live at both ends and verified. No live alignment occurs in this build.

Preserve current flags, URLs, bindings, crons, Google authority and deployed routing; repository example configuration is not a replacement for live settings. Deploy notes give owner-only order, the receipt/instructions/mass-apply/LSE checks, secret alignment, and rollback to the r bundle (`deploy/2026-11-11-v0.9.9r` at `38b353b`). Do not run the emergency authority rollback helper during an ordinary code rollback.
