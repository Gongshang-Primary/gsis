## Capture before processing

The authenticated frontend submits `saveAbsence` or `requestMutual` with an exact request ID. Pages strips client-supplied authority, time and Calendar proofs. With the existing optional `GSIS_JOBS` D1 binding, it validates and durably records the bounded command under the verified school identity before Google processing. Both Workers must share the same database and explicit Roster backend URL/public origin. The notification Worker also needs the existing Roster `BRIDGE_SECRET` to forward the original authenticated actor into Apps Script; this binding must be checked even if previously absent. The table/index are created automatically. No new secret or WhatsApp durable-ingress flag is required.

Without D1, current Contacts authorization and bounded command validation precede capture in a separate private Drive journal. This journal uses UserLock under the existing execute-as-owner deployment and never waits for the allocator's ScriptLock. Notification delivery shares UserLock: this isolates allocation contention, not all Google or lock latency. `ROSTER_ABSENCE_INTAKE_FILE` is created automatically.

Only a confirmed durable write returns a received receipt. Retain actor, command digest, request ID and trusted accepted timestamp across acknowledgement loss, browser closure and midnight. **Received** confirms capture; **applied** confirms the core absence; **peer approved** requires the colleague's explicit decision. D1 receipt authority is limited to transport: Apps Script rechecks current Contacts authority before applying school records.

## Independent processing and recovery

The notification Worker drains D1 into Apps Script intake, obtains current Calendar context, and applies records in bounded claimed work. Ordinary cron continues when automatic allocation or WhatsApp sending is disabled. `WHATSAPP_DIAGNOSTICS_ENABLED=true` intentionally selects read-only diagnostics and skips receipt processing; production must keep it false or unset for both capture modes. Deterministic child IDs and primary receipts prevent duplicate application after interrupted processing. Commit core absence before independent instruction and peer validation; their failures retain reviewable drafts without erasing the illness report. Preserve the original accepted timestamp when processing crosses midnight.

Show pending and needs-review work to the reporter and authorized SMC. An unforwarded D1 report in deterministic needs-review state can be withdrawn by SMC/Admin with actor, time and reason retained. This control cannot withdraw a forwarded report or delete an applied absence. Recovery retries retain the original command identity.

Known pending core dates gate allocation, publication and allocation-dependent timetable notices. Service-only D1 pending dates supplement the Apps Script journal. Unreadable intake blocks new timetable preparation while accepted provider outcomes in the same handoff can still be committed. Peer invitations and emergency receipts remain independent. D1 and Apps Script do not form a distributed transaction: capture during an already running commit queues the report for the next update.

Lock order remains ScriptLock then UserLock where both are needed. Capture never takes ScriptLock; provider calls run outside both locks. Source modules separate transport, intake, projection and peer mail, while the release retains one complete Roster Apps Script upload.

## Peer decisions and screen behavior

Proposal processing validates current identity, ownership, lesson and combination snapshot without doing allocation quota work during capture. Pending proposals reserve the affected demands and nominated colleague's periods from automatic allocation. They remain tentative cover until explicit peer acceptance revalidates current conditions and records protected human relief. Rejection, expiry and an audited SMC override release reservations. Audit identifies actor, time and overwritten choice; a stale approval cannot restore superseded cover.

WhatsApp and CES/GSPS email have independent durable outcomes. Email resolves current Contacts addresses, links to the authenticated My Relief Duties route and rechecks proposal status immediately before sending. Prepared sends without confirmed provider acceptance remain uncertain and visible; never automatically resend them. Capture does not wait for providers.

Show request processing, peer pending, peer approved and needs review separately. Keep Own arrangements local until the final submission. Remove the full-day shortcut requested in the screenshot while retaining explicit periods/timings, Select All, Clear periods, the period-confirmation button and final Submit absence.
