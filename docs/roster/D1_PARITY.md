## Evidence limits

Every discovered operation/view/action is called against the real edge dispatcher using a fresh in-memory SQLite D1 database and synthetic Contacts/timetable/R2 fixtures. Internal legacy writer rows are static persistence references, not public operations: their 204 reference-only outcome means no edge API should execute that Google helper. They are not counted as exercised request operations. Any actual outbound Roster request is checked against the canonical `rosterDispatch_` fence condition and real `rosterEdgeAssertLegacyWrite_` in an isolated VM. HTTP rows use unauthenticated GET probes, so authentication/method failures do not establish missing business logic. Scheduled Roster work is dispatched through the `scheduledRoster` service operation; no Apps Script `newTrigger` declarations exist in the scanned canonical Roster modules.

`works` means this synthetic request succeeded, not full Google/D1 semantic parity. `errors` includes intentional validation, missing fixture records, migration safety refusals and unsupported operations; the JSON records the exact result and probe family. A source handler link is not a passing functional test. `MISSING` means no discovered edge branch or a legacy/frozen Google path; all outbound attempts are trapped and never reach a remote service. Google-only means an explicit exception for legacy recovery/integration or a temporary inventory gap pending a separate Step 2 port, not permission to use a frozen writer.

Discovery parses canonical `backend/Roster*.gs`, the shared Google domain dispatcher, and Pages `_worker.js` equality branches, literal/constant includes-lists and operation sets. Source references and classifications are retained in `d1-parity.json`. Dynamic computed dispatch requires an explicit scanner extension; this is a static dispatcher inventory, not a proof of arbitrary runtime reachability.
