## Required (production-class)
1. Replace it with the **existing** accessible teacher combobox already used in Roster (`teacherPicker` in roster-update/public/roster-operations-ui.js, "Search teachers…"; also `combobox` in roster.js). Reuse or extract a shared helper; do not write a third picker.
2. In-place partial search: typing any part of the name filters as you type (case-, accent- and spacing-insensitive), matching the display name, the timetable name and bracket tags such as "(MTL)", "(FAJT)", "(Art)". Results sorted alphabetically; best matches (prefix) first.
3. Keyboard and screen reader: ARIA combobox pattern, Up/Down, Enter selects, Esc closes, Tab moves on; visible focus; clear "No teacher matches" state; works on touch screens.
4. Same option set as today (active teachers plus ad hoc/added teachers the current list contains); selection value unchanged (staff id), so saving tiles behaves exactly as before.
5. Tests: filter by partial text ("wati" finds Suriawati (FAJT)); tag search ("MTL"); keyboard select; no-match; saved tile carries the same staffId as before; Chromium check of the dialog.
6. Scope: Stapler UI only. No allocator, D1 or backend changes. If needed, stop and ask Claude.

## Implementation (Muse, 6 Nov 2026, branch muse/stapler-add-tile-teacher-search-rebase)
- Shared picker (`roster-update/public/roster-operations-ui.js`, `teacherPicker`): matching now folds text (NFKC, strip diacritics, lower case, collapse spaces) and matches the display name plus `timetableName`; with a query, results sort prefix-first (any folded token starts with the query), then alphabetical by name. With no query the caller's order is kept, so existing lists (e.g. the System Config bridge picker) are not reordered. The diacritic-strip regex is written with `\u` escapes, not literal characters, so the file still parses when served without a charset. No-match text unchanged. One robustness fix in the same function: `scrollIntoView` is now optional-chained, because jsdom (and environments without it) threw inside `mark()`; the error was new to the tile dialog path, verified absent on the pre-change test run.
- Tile dialog (`roster-update/public/roster-stapler-ui.js`): `fields()` renders a picker host plus a hidden `<input name="teacherId">` holding the current teacher; `bindFields(s,el,t)` mounts the picker with the plan teachers as `{id, name, timetableName}` and writes each pick into the hidden input, so `tileFields()` is unchanged. If `window.RosterOpsUI` is absent (e.g. a test loading only the Stapler UI), no picker mounts and the hidden input keeps the original teacher, so a venue-only edit still saves. `editTile` now also calls `reportValidity()` on submit, so an unmatched typed name blocks the edit as it already did for add. `editTile` shares `fields()`, so it gets the picker too; noted, not avoided.
- Effect outside Stapler: the shared picker's new matching and ordering also apply to Report Absence and Add teacher. Both were re-run and pass (see tests).
