## Failure and cause

At accepted claim `319ed2085a7b4f7281f3751eb8326bce500d701c`, the browser successfully staged a synthetic department. Save submitted the actual `patchPlanning` payload generated by the copied frontend. The real local `/api/deploy/change` returned HTTP503/SERVICE_UNAVAILABLE, leaving the original save reference and draft retained. The new department browser regression failed waiting for confirmed completion. Private local diagnostic: `gsis-departments-repro.log`; no school data was used.

The v1 model imported shared/fields.js as a module, but that classic browser script exports nothing. The built Worker therefore had no Fields.apply. Direct-operation tests had not exercised the browser's field-patch transport. The same fault affected department rename, removal, leadership/member saves, every organisation kind, duties and aSc export settings.

Use a v1-owned ES-module port of the existing stable-field encoding, leaving shared v0.9 source unchanged. Check patch shape and optimistic field preconditions before reconstruction. Malformed reconstruction now returns a definite validation error instead of an unconfirmed service exception. Keep the existing lease, school, capability, owner revision, operation identity, receipt and recovery boundaries.
