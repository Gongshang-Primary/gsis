# SMC capacity warnings and weekly outlook

Follow-up to [the capacity projection](../accelerated-delivery/RELIEF_CAPACITY.md), based on PR146 `692ea365522cd90c4961b7e6fb43072848253677`. Roster owns notification generation; Contacts, Deploy and Calendar retain their existing authoritative roles.

V1 replaces newly generated legacy capacity warnings with the actual layered allocator's eligibility projection after ordinary quota-bearing mutations and allocation. It restores the previous warning episode state before applying the new projection, so old calculations do not consume a warning threshold. Existing queued/sent/uncertain jobs remain intact. The existing 2/1/0 thresholds, duty-SMC recipient checks, quiet hours and per-period episode deduplication remain. Unknown evidence does not create a false zero-capacity warning.

Configured morning/evening summaries include the rest of the target school week. The first configured summary in each phase carries this outlook; later unchanged-absence summaries retain existing deduplication. This is not continuous delivery on every forecast fluctuation. It reports known demand, projected uncovered periods and unverified dates, with an explicit bounded-solver caveat. It suggests considering external ad hoc relief when cover remains unresolved, but never activates staff. Green choices overlap and are not additive R or guaranteed cover.

Delivery refreshes capacity and the forecast from current owner evidence, preserving current recipient, consent, duty membership, expiry, outbox lease and uncertain-result handling. Superseded/started/past or unverified critical warnings cancel; provider/source outages retain existing failure handling. Reports label unknown capacity. The refreshed message is an as-of projection, not a reservation or a cross-D1 snapshot. Actual allocation still validates its inputs before committing. No provider is called by these tests.

Existing template keys `capacity_warning`, `relief_morning` and `relief_evening` map the documented duty name/date, capacity or absence summary, health summary and Roster URL parameters. See `docs/WHATSAPP_PARAMETERS.md` and `notification-worker/template-contracts.json`. Repository approval records are not proof of current Meta availability. Keep approved names, language and parameter order in the protected deployment configuration. The provider-secret setup is separately reviewed in PR149; this PR uploads no credential, registers no webhook and activates no scheduler or sender.

Verification: new focused notification program covers recipients, quiet hours, deduplication, legacy replacement, unknown evidence, template aliases, actual local D1 refresh and stale cancellation. Existing real Roster service tests cover committed mutations/allocation and disabled scheduler truthfulness. Canonical build, full product and Node/LORD exact-head CI results are recorded in the PR. Runtime UAT is Not tested. F5 remains OPEN. Rollback returns to legacy warning calculations; it does not erase queued delivery history or receipts.
