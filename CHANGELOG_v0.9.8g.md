# GSiS revision G changelog

Baseline: v0.9.8f. All supplied suite components use v0.9.8g.

## Deploy

Renaming to an occupied class name temporarily displaces the prior holder to level(undefined). This works at every level P1 to P6. Multiple temporary rows keep distinct stable references and retain their respective teachers, subject allocations, teaching groups and venues.

Class rename drafts recover in the same browser for the same signed in account and deployment version. Final Save rejects unresolved temporary names. Resolved swaps and rename cycles use one validated batch with existing locking, receipts, authorisation and stale value protection. Changed saved names require review; uncertain submitted commands keep their original request identity.

## Shared API configuration

GSIS_SECRET is the common first party transport credential. The user supplies exactly 32 printable ASCII characters excluding whitespace. A configured value takes precedence; invalid configuration fails closed without exposing the value. If absent, the existing per connection configuration still works.

The update covers Apps Script and Cloudflare incoming and outgoing GSiS API connections. Action restrictions, identity checks, expiry and replay protection remain. Provider credentials, browser session keys, private links and booking peppers keep their separate purposes.

## Roster exports and teacher navigation

Stapler export uses Teacher Summary and Class POV tabs. Roster workbook period grids include source start and end times immediately above the period headings, within the frozen rows. Existing identity columns stay frozen. Non period list and statistics exports retain their own structure.

Teachers can view confirmed suspended dates in Stapler and use its link to open their own suspended timetable. Teacher access stays read only and excludes planner drafts, other teachers' private timetable views and SMC editing controls.

## Setup guidance

The setup guide includes matched component installation, a coordinated optional shared key cutover, rollback and D1/private R2 preparation. It checks existing storage before suggesting new empty resources.

Roster timetable cache data flow, horizon, pruning, flags and authority are unchanged. No new cache activation, data migration, Worker or Queue is required. The active relief assignment ledger remains deferred. Earlier D, E and F behaviour remains in the matched sources.
