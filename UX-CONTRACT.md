# GSiS Roster interaction contract

See DESIGN.md for the established visual design. Runtime authority stays on the backend; Home visibility is a convenience, not access control.

1. Navigation retains unsaved-edit checks and pending-request recovery. Date responses must match the current date and render ticket before replacing the screen.
2. Local teacher/subject search, wildcard previews, period selection and preference ordering do not call the server.
3. Saves include a stable request ID and loaded revision. A transport failure offers the same request again. A conflict retains input, fetches the latest revision and asks for review before another save.
4. Background reads and saves show one inline yellow progress message with elapsed time where available. They leave unrelated controls usable and preserve local edits. Use a blocking dialog only for a user-opened modal task or a version transition that would otherwise allow editing the wrong data. Completion and error feedback stay within the current page or open dialog.
5. System Config allows SMC and Admin to read; only Admin can save changes. Baseline Upload requires Admin. Other existing saved-baseline management retains SMC authority. Normal authenticated teachers can read Daily Updates, including recorded absence reasons. Admin and SMC alone can edit its settings or queue a report.
6. Subject rules and allocation order are unsaved until Save changes. Saving settings does not publish a timetable or run allocation. Subject rules apply to new absence reports; saved entries remain unchanged.
7. Daily report dates distinguish a live current-day preview from an original stored snapshot. Historical reports are unavailable when no snapshot exists. Manual send requires a published date and uses the saved recipient addresses.
8. Known contacts retain their effective employment modifier. New contact creation requires name and mobile. Duplicate TTb name or mobile blocks another record. A failed daily activation after successful contact creation retries activation, not creation.
9. Use native labelled date/time inputs and buttons. Search results, chip removal and priority movement support keyboard interaction. Dialog progress prevents duplicate submissions and restores focus afterward.
10. No new build or opening a page sends live messages by itself. Messaging follows configured runtime gates, publication state and explicit actions.

11. In Report Absence, "I'm not available in these selected periods" prepares the selected-period instruction preview without writing. Relief instructions remain visible as a section, with no expand/hide control. The No relief instructions choice appears beside the Absence date selector above the rows, changes local state, preserves text and does not submit. The bottom Submit absence action is the only initial save and includes the report and its instruction choices together. Keep the saved section visible, offer Own arrangements only for saved records, and save later instruction changes through the bottom Save instructions action. No relief instructions does not remove the need for relief or become a preference for later teachers. Uncertain outcomes retain the exact request for recovery.
12. Name Bridge uses one locally searchable combobox for exact baseline teacher names. Clearing removes the selection and restores focus. Custom text cannot be saved; stale retained mappings are shown for review. Contacts identity selection stays separate.
13. Relief Health period visibility is a display choice. Explain full-day totals and keep paired teacher markers intact when assigned reds stack from the axis upward. Employment-period restrictions instead affect automatic eligibility; explicit manual exceptions require a reason.
14. Tier 1 contains all eligible internal manual suggestions and leads with remaining weekly R descending, then timetable fit and fairness. Explicit override, external and repurposed recess groups stay separate. Automatic allocation still follows its separate configured preference order.
15. Duty-summary times use Singapore time and show whether they concern the next day or current day. Explain the fresh 05:30 summary and later unchanged suppression. Saving this setting does not send a message immediately.

16. Assign Relief Export Excel includes every teacher in four Subject, Class, Venue and Group rows, with absence and relief styling. Export relief excel preserves the arrangements-only workbook. Export does not save or publish.
17. Import Offline JSON resolves names against eligible Contacts before applying final placed tiles for the selected day. Source lesson differences do not block import. Included teachers receive their whole final day, including blanks; missing teachers retain baseline. Unresolved names and invalid placements keep the draft unchanged. Preserve custom classes, venues and staffed recess; exclude offline Card Pit. Saved offline absence and relief labels are final-overlay annotations, not online attendance, credits or notifications. Confirmation supplies the same working timetable to summaries, Excel and relief allocation. Exclude SLs, MK and OSO from import matching. Adding a contact retains the draft and selected mappings; fuzzy matches are never silently accepted.
18. Automatic allocation retains hard eligibility and maximum coverage as fixed policy, then minimises the saved ordered business-rule score. The six defaults are annual R utilisation, alternative periods, weekly R remaining, rotation, same level, then same subject. Each preference has its own on/off toggle. The first v0.7.16 settings migration moves same subject to the bottom once; later saved ordering is retained. A bounded result states whether the preference minimum was proved or is the best found.

19. Home uses the 20-icon order in queued item 016, with the divider after the permitted members of positions 1 to 8, ending with WhatsApp Inbox. Role filtering never leaves blank tiles. Display Suspended Timeable Advance PLannER without renaming persisted/API identifiers.
20. Own absence entry is available from Home and the #reportAbsence deep link, preserved through sign-in. Start/End dates stay close beside each other; individual timed period selectors stay visible. Periods begin unselected, with Select All and Clear. No Today/Tomorrow/Both or Full/Partial controls replace these fields. Existing reason, instructions, overlap, request retry and current-authority checks remain.
21. Calculations resolves the current authenticated teacher on the server. Do not expose another person's records through a selector or load personal calculations before the page is opened. Missing source/history shows Unavailable, not zero. Completed relief excludes planned and future work; its denominator is recorded accumulated entitlement, not an estimate for unrecorded weeks.
22. Enabled daily and consecutive caps are strict automatic-allocation constraints, defaulting to 9 and 6 only when absent. Count distinct effective lesson, relief and invigilation periods. Other duties still block availability. Toggle and ordering changes take effect only after Admin saves.
23. Accepted suspension validation is retained with plan content, date, baseline, record revision and rule version. A legacy saved plan is fully checked and receives stored proof on its next successful Save/Confirm. Reads do not write. Current permissions, Calendar, editing lease, revision and operational constraints remain authoritative.
24. WhatsApp Inbox must distinguish configuration readiness, a read failure and an empty successfully loaded Inbox. A package or readiness result does not establish live ingestion, private media or delivery.

25. Initial own-report data may share the authenticated profile response. Incompatible or missing data uses the ordinary report read; a failure is not an empty record list. Identical in-flight reads can share work, but a late response cannot replace a newer date or pending input.
26. An accepted exact absence receipt confirms the save even when a later view refresh fails. An absent receipt remains unconfirmed. Never create a new request identity merely because a response is slow.
27. Stapler Rename preserves content and confirmation. Change date and Restore require a compatible vacant destination and become Draft. Delete retains a recoverable archive. Current authority, plan revision, editing ownership and protected history are enforced by the backend.
28. Assign Relief uses equal-height toolbar rows: 40px desktop controls and 44px mobile/touch controls. Export Class POV, Absent Teachers and Relief Load precede Refresh records. Class POV covers the full effective selected day. Summaries are read-only views of loaded saved absences and assignments, with current-period counts rather than annual relief utilisation. Closing a summary restores focus; neither opening nor exporting writes or publishes.


## Contacts: item 083

The lowercase add column precedes TTb Name. A text + has a keyboard-accessible button and focus outline, horizontal touch padding, and no added vertical height. Export one selected person's VCF locally on demand. Preserve complete TTb and Statutory names in first and last name fields, with GSPS as prefix. File export cannot claim successful device import or automatic synchronisation. A retry download link and import guidance remain available; sign-out removes temporary links. No Google Contacts authorisation, shared-directory write or personal address-book scan occurs.

## Ownership setup

`shared/edge-setup.js` owns the Roster/Deploy operator interaction contract. The app's existing same-origin school session is the credential source. A status request is read-only; every mutation needs an explicit action and fresh server authorisation. Access denial blocks actions and directs the operator to sign in through the main app. Import retries keep one tab/session request ID; a restart clears that identity only after a confirmed reset. Exports download privately and are not rendered or persisted in browser storage. Activation requires an export-review check and a cancel-first confirmation, and uses the exact Roster source digest when required. A local checkbox never replaces server fence verification. Errors retain recovery identity. No automatic mutation, source reset or authority fallback is permitted.
