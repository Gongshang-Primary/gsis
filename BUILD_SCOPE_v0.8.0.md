## Package and installation boundary

The full package contains five Pages frontend ZIPs, three complete Apps Script backend files, the separate notification Worker, source, documentation and verification evidence. For all new Roster benefits from v0.7.19, update Contacts backend → Deploy backend → Roster frontend. Older compatible Contacts full-directory responses remain supported, but cannot supply the new small projection. Calendar and the other frontends are optional functional updates for this release; the existing compatible notification Worker can remain installed.

Keep Staff IDs, `/exec` URLs, properties, secrets, saved rules, operational data, private media binding, cron and activation flags. Do not run blank setup or replace saved data to upgrade. No new service or storage migration is introduced. Whole-document operational commits remain serialized.

## Evidence and deferred work

The implementation removes bounded work and blocking presentation. Production timing, Google service tails and simultaneous school-user throughput require installed measurements. Optional parallel Drive reads and a storage-layout rewrite are deferred until measurements justify their broader contracts. The existing saved-plan and uncertain baseline incidents are not closed by local fixtures.

`VALIDATION.md`, `PERFORMANCE_v0.8.0.md` and `RELEASE_SUMMARY.json` identify actual checks and remaining limits. Building and committing this package does not deploy it, change production configuration, publish a school day or send messages.
